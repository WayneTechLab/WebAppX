# SYSTEMX for the unified public webapp template

The current universal operating standard is provided by the managed standalone
[dotSYSTEMX](https://github.com/WayneTechLab/dotSYSTEMX) release. Read the selected
release's START-HERE and STANDARD alongside this project's outer context and
records. `npm run systemx:status` identifies that release and checks integrity.

Use [the host integration guide](../docs/SYSTEMX-INTEGRATION.md) for ownership,
version selection, menus and repeatable public-source imports. `SYSTEMX.sh`
executes selected defaults; `WSG-MENU.sh` retains the webapp lifecycle. Adopted project
tasks live in `WORK/TASKS.json`; legacy `status/` files retain the LAN
feature roadmap. The sections below describe retained webapp extensions.

## SYSTEMX host swarm — Agent 0, X/Y/Z and Alpha

The [host swarm guide](../docs/SYSTEMX-SWARM.md) defines one canonical Agent 0
integration owner, Agent X event observations, up to ten authorized Agent Y CLI
slots with independent task-generation branches/worktrees, Agent Z independent
review and Alpha integration assurance under a bounded policy lease. Read the
[operational map](../docs/SYSTEMX-SWARM-MAP.md) and
[access matrix](../docs/SYSTEMX-SWARM-ACCESS-MATRIX.md) together.

Automatic PR integration requires the exact repository, PR, head/base, accepted
independent review, passing required checks, a current lease and conflict-free
provider protection state. Keep review work on its open task PR; after accepted
work and verified merge, preserve and verify owned cleanup before reusing a slot
with a fresh generation branch. Mac IDE/Codex handoffs invalidate on revision,
branch, dirty-state or generation drift. Local tests do not establish live CLI,
GitHub merge, branch deletion or IDE acceptance.

This is a host extension above managed SYSTEMX 1.9.0-alpha.6. It preserves release
snapshots and blank reusable seeds. Its operating support does not inflate LAN
acceptance counts or authorize production deployment.

## SYSTEMX LAN builder

The local builder plan lives in [`LAN/`](LAN/README.md). It is designed to
re-imagine the reusable visual-CMS patterns from
[WTL-Instatic](https://github.com/WayneTechLab/WTL-Instatic) for this
Firebase/Vite template. The target is the current checkout in
`template-edit` mode: inspect and safely edit existing pages, routes, modules,
tokens, collections, and assets while previewing through Vite and Firebase
emulators.

The builder's provider model keeps the storage choices explicit:

- Firestore and optional Realtime Database for document/realtime workloads;
- Firebase SQL Connect backed by Cloud SQL PostgreSQL for relational workloads;
- Cloud Storage for Firebase for web media;
- Google Drive/Shared Drive for operator documents and production-kit files;
- Google Cloud Storage for approved internal archive workflows.

These are separate capabilities with separate security and sync rules. The LAN
surface is loopback-only, runs outside the public app build, and delegates
quality, security, and deploy authority to the existing `.SYSTEMX` CLI.

The LAN is also the planned co-management control plane for the codebase:
named tool actions, backend/source diagnostics, humanized run states,
sanitized logs, Agent 0 checkpoints, subagent handoffs, provider preflight, and
last-deploy evidence. See
[`LAN/CONTROL-PLANE-PLAN.md`](LAN/CONTROL-PLANE-PLAN.md) for the execution
waves and safety contract. Backend function or provider-file editing remains
gated until its file-class validator, backup, diff, secret scan, and post-write
quality checks exist.

Start the current-template WebApp, LAN service, and Auth, Firestore and Storage
emulators together with:

```bash
npm run dev:systemx
```

The default launch selects free loopback ports. For a stable browser-save
origin, select an explicit app hostname and port:

```bash
npm run dev:systemx -- --host 127.0.0.1 --port 5185
```

The selected session exposes:

```text
http://<app-host>:<app-port>/           # public app
http://<app-host>:<app-port>/portals    # native demo directory
http://<app-host>:<app-port>/__systemx/ # LAN through Vite dev proxy
http://127.0.0.1:<lan-port>/            # LAN direct loopback service
```

Use the exact **Mock save origin** and `/portals` URL printed by the supervisor
or recorded by `npm run systemx:session:status`. Native demo saves belong to
that HTTP scheme, hostname, port and browser profile. `localhost` and
`127.0.0.1`, different ports, and different browser profiles have separate
storage. Keep the same printed address to reopen those saves.

`--host` accepts `127.0.0.1` or `localhost`; `--port` selects the app port.
Supplying either option, `SYSTEMX_DEV_HOST`, or `SYSTEMX_APP_PORT` fixes the app
origin. `--fixed-origin` or `SYSTEMX_FIXED_ORIGIN=true` pins the defaults when
no origin overrides are set. An occupied fixed app port fails before children
start or runtime state is written, without falling back to another app port.
Vite always uses `--strictPort` to catch races after port selection. Default
automatic selection checks both IPv4 and IPv6 loopback availability. The LAN
and emulators bind to `127.0.0.1` and select their ports independently.

The ignored `.SYSTEMX/state/local-session.json` records the origin, URLs,
process identities and separate `app`, `lan`, `auth`, `firestore` and `storage`
readiness entries. Each is `starting`, `ready` or `failed`, with its own message,
URL and timestamp. The Vite app can be usable while an emulator is still
starting or has failed. Storage readiness establishes a reachable TCP listener;
it does not establish a working Storage workflow. These startup observations
and process exit updates do not establish continuous or provider health.

Use the session controls for start-of-day/end-of-day ownership:

```bash
npm run systemx:session:status
npm run systemx:session:restart:preview
npm run systemx:session:stop
```

`status` adds current process observations to the recorded session; `recorded`
is not an aggregate readiness verdict. On macOS, combined-session `stop` verifies
recorded live-process ownership, then signals its supervisor so that owner can
stop the children and clear runtime state. Windows combined-session stop refuses
with `windows-combined-stop-requires-owning-terminal`, signals nothing and
preserves record/configuration files. Press **Ctrl+C in the owning terminal**,
then inspect child processes, listeners and any remaining state before recovery.
A verified standalone Windows LAN stop can terminate its single process; wait
for exit and rerun stop if its record remains. A refused stop preserves files.
The restart command runs only
`restart --preview`: it inspects process ownership and replacement listeners
and prints a `ready-for-review` or `refused` proposal preserving the recorded
origin and ports. It starts no children, signals no processes, and changes no
session state, token or runtime configuration. A mutating restart action is
not implemented. Recheck ownership and listeners before a later restart. Read
the [LAN session contract](LAN/README.md#local-sessions) for readiness evidence,
preview fields, refusal cases and exit codes.

The native demos retain complete saved workspace records at the selected app
origin. Per-portal and combined backups download readable JSON of current
accepted records, including saved drafts and accepted in-memory changes whose
browser save failed. Exports cover complete workspaces independently of a
preview role; unsaved forms, running timers, recovery history and the separate
Gusto SDK session are excluded. Selective restore and Undo replace selected
whole workspaces and first save a recovery point. A dirty CMS author editor
survives import/restore/Undo for explicit comparison and Reload/Reapply; accepted
Reset clears it. Independent origin-local settings, initially off, can require a
module-only checkpoint before individual import or Reset. Unknown/damaged
settings refuse replacement; known-off Reset keeps its one-click behavior.
The volatile editor, retained navigation drafts and these settings are excluded
from workspace exports. Reset preserves recovery
history, and clearing that history is a separate action. Use fictional data
only and follow any displayed export/recovery guidance before refreshing
after a storage failure. The complete behavior is defined in the
[portal state and browser retention contract](../docs/PORTAL-STATE-CONTRACT.md)
and [portal capability vocabulary](../docs/PORTAL-CAPABILITIES.md); synthetic
roles and backups do not grant Firebase or provider authority.

This G1 builder shows controller health, Vite preview status, repository state,
builder waves, route inventory, provider readiness, source files, page models,
typed modules, CMS/CRM fixtures, local account fixtures, and a Font browser
with loaded-font inventory. It can write
allowlisted local source and model changes only with a session token, backup,
secret scan, operation evidence, and explicit confirmation. The workspace and
provider contracts are under `LAN/Builder/`; live cloud mutations remain
separate authenticated adapters and the existing `.SYSTEMX` quality/deploy
gates remain authoritative.

The active UI contract is canvas-first: left structure dock, center Vite
preview, icon-first right tool rail, docked right inspector open by default in
a fresh layout, and a `Layers` bottom dock for page-model work. The Style
inspector can preview Google Fonts CSS2 families in the live Vite frame and
save a selected project font only after `SAVE FONT CHANGE`. Local evidence is documented in
[`../wiki/SYSTEMX-Logs-and-Evidence.md`](../wiki/SYSTEMX-Logs-and-Evidence.md)
and recorded under ignored LAN runtime folders.

Font reads and confirmed saves now carry the exact stylesheet revision;
**Refresh font source** is explicit, and a font save does not rebase an open raw
CSS draft. The Code inspector's **Preview draft** captures literal text with its
loaded source baseline and draft digest. **Check source** reports current,
advanced, unavailable or unknown state through a source GET; **Close preview**
keeps the editor. It executes no source and creates no source-write authority.
Read the [font/preview QA receipt](../docs/LAN-FONT-PREVIEW-QA-2026-10-28.md) for
actual tests and the [active iteration](../docs/LAN-ACTIVE-ITERATION.md) for the
current goal. Managed release snapshots remain unchanged.

The left and right editor docks have independent close controls plus an
explicit **Keep open / Always shown** policy button. Auto visibility is the
default; the layout save loop reconciles dock classes and pin state so source,
page-model, refresh, and responsive-width operations do not unexpectedly
reopen or collapse an editor menu.
